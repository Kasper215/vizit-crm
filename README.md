# CRM «ВИЗИТ ДОНЕЦК»

Единая система заявок редакции. Веб-CRM в браузере и Mini App в Telegram используют один Node.js API и одну базу SQLite: изменения между ними синхронизируются сразу.

## Возможности

- Список заявок, поиск, этапы работы, воронка, сроки, история, файлы и экспорт CSV.
- Бот импортирует сообщения из рабочей группы и личные пересылки; перед сохранением показывает редактируемый черновик.
- Бот предупреждает о совпадении телефона и позволяет присоединить документы к уже существующей заявке.
- Команды и быстрые действия в чате: поиск, сводка и заявки, по которым пора связаться.
- Ежедневная сводка в Telegram по срокам контакта.
- Голосовые заметки сохраняются в карточке как аудиофайлы. Расшифровка выключена по умолчанию и включается только после настройки OpenAI API key.
- SQLite — основное хранилище. При первом запуске данные из `data/applications.json` копируются в `data/crm.sqlite`; исходный JSON сохраняется.

## Локальный запуск

Нужен Node.js версии 22.13 или новее. В PowerShell из папки проекта:

```powershell
$env:PORT='4175'
npm.cmd start
```

Откройте <http://127.0.0.1:4175/> для браузерной CRM или <http://127.0.0.1:4175/miniapp> для Mini App-просмотра. Локальные страницы используют общий API и SQLite.

## Подключение бота

Скопируйте `.env.example` в `.env` и заполните токен бота, ID рабочей группы и свой числовой Telegram ID. Если запускаете CRM на 4175, задайте этот порт и в окружении бота. Для PDF-разбора установите Python-зависимость и запустите CRM и бота в отдельных окнах:

```powershell
python -m pip install -r requirements.txt
npm.cmd start
npm.cmd run telegram
```

В группе бот должен видеть заявки: добавьте его администратором или настройте Privacy Mode через BotFather. В личном чате `/id` показывает ID пользователя. Укажите его в `TELEGRAM_ALLOWED_USER_IDS`; только перечисленные ID смогут пересылать заявки, запускать рабочие действия и открывать удалённый Mini App. Несколько ID разделяются запятыми.

## Общая база браузера и Mini App

Обычная CRM `/` и Mini App `/miniapp` обслуживаются одним сервером. Они читают и изменяют одну базу SQLite; отдельного импорта или синхронизации между интерфейсами нет. В режиме разработки API разрешён с loopback-адреса. В production доступ к API проверяет HMAC-подпись `Telegram.WebApp.initData`; процесс бота обращается к CRM с `CRM_API_TOKEN`.

Для открытия из Telegram нужен публичный HTTPS-адрес. Укажите его в `TELEGRAM_WEBAPP_URL`; при старте бот установит Mini App как кнопку меню личного чата. Сам проект не публикует домен автоматически.

## Настройки

Скопируйте `.env.example` в `.env`. Основные переменные:

| Переменная | Назначение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен бота из BotFather |
| `TELEGRAM_ALLOWED_CHAT_ID` | ID рабочей группы для автоматического разбора новых заявок |
| `TELEGRAM_ALLOWED_USER_IDS` | Разрешённые ID владельцев/сотрудников, через запятую |
| `TELEGRAM_WEBAPP_URL` | Публичная HTTPS-ссылка на `/miniapp` |
| `CRM_API_TOKEN` | Секрет для внутреннего доступа бота к CRM API |
| `TELEGRAM_DIGEST_TIME` | Время ежедневной сводки, по умолчанию `09:00` |
| `TELEGRAM_TIMEZONE` | Часовой пояс сводки, по умолчанию `Europe/Moscow` |
| `OPENAI_API_KEY` | Необязательно; только для расшифровки голосовых заметок |
| `OPENAI_TRANSCRIPTION_MODEL` | Модель транскрипции; по умолчанию `gpt-4o-mini-transcribe` |
| `HOST`, `PORT`, `DATABASE_PATH` | Адрес сервера, порт и путь к SQLite |

Когда `OPENAI_API_KEY` пуст, аудио остаётся в CRM как файл и не отправляется внешнему сервису. Если ключ настроен, бот пересылает аудио провайдеру для транскрипции.

## Git и конфиденциальность

Проект инициализирован как **локальный Git-репозиторий** в этой папке. Удалённый репозиторий GitHub не создавался и push не выполнялся. `.env`, SQLite, исходные заявки, документы и журналы исключены из Git. Не отправляйте клиентские данные или секреты в публичный репозиторий.
